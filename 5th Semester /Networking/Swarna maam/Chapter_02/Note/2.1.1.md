
## 🌐 2.1 Principles of Network Applications — সহজভাবে

### 🧠 মূল ধারণা:
তুমি যদি একটা নতুন network application বানাতে চাও (যেমন WhatsApp, Netflix, বা কোনো নতুন app), তাহলে তোমাকে এমন software লিখতে হবে যা **বিভিন্ন device-এ চলে** এবং **network-এর মাধ্যমে একে অপরের সাথে যোগাযোগ করে**।

---

### 📱 উদাহরণ:
- **Web Application**:  
  - Client: Browser (Chrome, Firefox) → তোমার ফোন বা কম্পিউটারে চলে  
  - Server: Web server → Google বা Facebook-এর server-এ চলে

- **Netflix**:  
  - Client: Netflix app → তোমার ফোনে  
  - Server: Netflix server → Netflix-এর data center-এ

---

### 🚫 কী করতে হবে না:
তোমাকে **router বা switch-এর জন্য software লিখতে হবে না**। কারণ এগুলো **network-এর core device**, আর application layer-এ কাজ করে না।  
তোমার কাজ শুধু **end systems** (যেমন ফোন, কম্পিউটার) এর জন্য software বানানো।

---

## 🏗️ 2.1.1 Network Application Architectures — দুইটা মূল ধরন

### 1️⃣ Client-Server Architecture

#### 📌 বৈশিষ্ট্য:
- **Server সবসময় অন থাকে**  
- **Client শুধু request পাঠায়, server response দেয়**
- **Clients একে অপরের সাথে সরাসরি যোগাযোগ করে না**

#### 🎯 উদাহরণ:
- Web (browser ↔ server)
- Email
- FTP
- Telnet

#### 🏢 Data Center:
যখন অনেক client request পাঠায়, তখন একটাই server যথেষ্ট হয় না। তাই বড় বড় কোম্পানি (Google, Amazon) **data center** বানায় — হাজার হাজার server থাকে সেখানে।

---

### 2️⃣ Peer-to-Peer (P2P) Architecture

#### 📌 বৈশিষ্ট্য:
- **কোনো central server নেই**
- **সব peer (user-এর device) একে অপরের সাথে সরাসরি যোগাযোগ করে**
- **সব peer নিজের মতো করে কাজ করে — যেমন ফাইল শেয়ার করে**

#### 🎯 উদাহরণ:
- BitTorrent (ফাইল শেয়ারিং)

#### ✅ সুবিধা:
- Self-scalable: যত বেশি peer, তত বেশি capacity
- Cost-effective: server লাগে না

#### ❌ সমস্যা:
- Security, reliability, performance — সব decentralized, তাই চ্যালেঞ্জ বেশি

---

## 🔁 Client-Server vs Peer-to-Peer — তুলনা

| বিষয়              | Client-Server                  | Peer-to-Peer (P2P)             |
|-------------------|-------------------------------|-------------------------------|
| Server            | Always-on central server       | No central server             |
| Communication     | Client ↔ Server                | Peer ↔ Peer                   |
| Scalability       | Limited by server capacity     | Self-scalable                 |
| Cost              | High (server, bandwidth)       | Low (user devices)            |
| Examples          | Web, Email, FTP                | BitTorrent, Skype             |
